## 一、裁决问题

`WZCityTCDS` 应当成为：

- **Option A**：城市时空可信内容枢纽（City Spatial-Temporal Trusted Content Hub）的正式事实出版内核（Formal Fact Publication Kernel）；还是
- **Option B**：建立在城市时空可信内容枢纽之上的独立公共事实服务。

判断依据不是“是否使用独立仓库、域名或独立进程”，而是事实权威的法律与业务责任、实体主数据生命周期归属、单双向投影机制、对外发布与更正撤回的独占生命周期。

---

## 二、裁决结论

**仓库所有者裁决结果：正式采纳 Option A（城市时空可信内容枢纽的正式事实出版内核）。**

### 核心决议要点：
1. **定位明确**：`WZCityTCDS` 定位为城市时空可信内容枢纽的官方事实出版内核，专门负责权威结构化事实的生产、审核、仲裁、不可变版本链管理与事实签发；
2. **实体主数据单根归口**：不从零构建第二套城市实体身份体系或别名主库。实体身份、实体别名（Alias）、实体重定向（Redirect）统一归口于城市时空可信内容枢纽主数据底座；
3. **单向受控投影机制**：本系统独占事实候选、人工审核、事实断言（FactAssertion）、出版快照（Publication）的写生命周期；签发事实单向受控投影至枢纽全域检索与下游消费，枢纽侧不得形成第二个自由写入方；
4. **发布与更正责任闭环**：本系统负责事实出版版本链（FactRevision / PublicationRevision）、证据片段（EvidenceSpan）精确哈希溯源，以及事实更正与撤回审计。

---

## 三、裁决依据

1. **业务设计沿革契约一致**：
   锁定基线设计文件（`docs/温州有据_主题事实档案升级需求_PRD_v1.1.md` 及 `docs/温州事实稿_v2/docs/02_与现有系统衔接方案.md`）明确指出：“归一以城市时空可信内容枢纽的实体 ID 为唯一锚点，不建立平行实体主数据，采用逻辑主记录 + 单向受控投影”。Option A 严格继承并固化了这一权威架构规约；
2. **杜绝实体数据脑裂与治理冗余**：
   若采纳 Option B，本系统必须独立承担城市实体、时空图谱、多源冲突治理及高昂的外部 SLA 承诺，不仅造成严重的重复建设，且必然导致跨系统实体身份与事实冲突难以调和；
3. **权责明晰且保留独立演进空间**：
   Option A 明确了“领域从属、服务独立、契约受控”。WZCityTCDS 具备独立的接口版本化治理、代码演进与质量门禁，既受控于枢纽的实体约束，又独占事实签发权威。

## 四、后续直接工程约束

随着本决策的关闭（`CLOSED: OPTION_A`），后续开发必须严格遵守以下红线：

1. **白名单与实体约束**：
   后续切片禁止在本地创建任何形式的“独立城市实体编辑/新建”主数据后台；遇到未收录实体必须走枢纽实体治理提案流程；
2. **下游切片输入基准**：
   - **S2 阶段**：仅设计与枢纽 `EntityResolver` 对齐的接口适配器，以及上游 CMS 语料接入规范；
   - **S3 阶段**：实现不可变事实版本链与签发状态机；
   - **S4 阶段**：实现字符级证据（EvidenceSpan）与哈希验签引擎；
   - **S5 阶段**：实现面向 Web、API、Feed、Sitemap 及 MCP 的已签发快照出口；
3. **治理状态更新**：
   本决议关闭后，作为 S1 架构定位审查里程碑的正式结论，归档入库。
